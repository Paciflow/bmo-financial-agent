BMO Financial Intelligence Agent — architecture

Two pipelines: an offline job that turns the PDF into searchable chunks once, and an online request that turns a question into a cited answer every time it's asked.

Offline — ingestion (runs once per document)

Everything above the dashed line happens before any user ever asks a question. The PDF never gets re-read at query time.

Online — a query, start to finish

The blue path is grounded in retrieved document evidence; the amber dashed path is the model's own pretrained knowledge. A question takes exactly one of these two paths — they are routed, not blended, inside a single answer.

Design question: should "acquired" context be expanded?

What "acquired" is, and why it should stay narrow

"Acquired" here means exactly one thing: Claude's own pretrained financial knowledge, used only when classify routes a question to the general path — a question that isn't about this specific document at all (e.g. "what's a P/E ratio?"). On that path, retrieval never runs, and the system prompt explicitly forbids presenting that answer as if it came from BMO's filing. This matches the system's own design requirement: cite document answers, don't fake citations on general ones.

The alternative — always blending retrieved passages with the model's general knowledge inside one answer — sounds more capable but isn't the safer default for this use case. Two reasons: first, every number in a document answer has to be traceable to a specific page, and the moment general knowledge gets woven in, a reader can no longer tell which sentence is sourced and which is the model's own recall. Second, widening the evidence context doesn't reliably improve accuracy — it competes against relevance. We measured this directly: dense-only retrieval scored lower than hybrid, and the biggest retrieval win this session came from fixing a chunk-quality bug, not from adding more passages to the context window.

Where blending does genuinely help — interpreting a figure ("is 13.3% CET1 strong?") — the document itself usually already states the regulatory benchmark, so the honest fix is better retrieval, not injected outside knowledge. One small, deliberate exception is already wired in: the answer prompt is allowed to add a brief, clearly-labeled interpretive note after the cited facts, never instead of them.

For an associate-level demo prioritizing accurate over exhaustive: keep retrieval lean (today's 6-passage evidence set, tuned via the eval harness), keep the two paths separate, and don't expand context just to seem more thorough. More context without a measured accuracy gain mostly adds latency and dilutes precision.
